# 带充电底座的耳机（HECATE G5 MAX 底座版） —— 播放设备自动切换方案

[English](README.en.md) | 简体中文

我用的耳机是带充电底座的（HECATE G5 MAX 底座版）。把耳机放回底座、它自动关机之后，
Windows 的播放设备列表里**那个耳机还在**，默认设备也还是它 —— 于是整个系统就静音了，
每次都得手动去「声音设置」里切回扬声器。因此我自己设计了一个后台自运行小工具来解决这个问题。安装后的效果：

| 动作 | 耳机状态 | 工具效果 |
|---|---|---|
| 从底座拿起耳机 | 语音播报 "开机，2.4G模式已连接" | 音频切入耳机 |
| 把耳机放回底座 | 语音播报 "关机" | 音频切回原扬声器  |

不用安装驱动，不会开启窗口，开机自动生效。

> ⚠️ **不要同时开着漫步者驱动（HECATE.exe）。** 驱动和本工具会争抢底座同一份 HID 数据流，
> 谁先读走就归谁 —— 驱动开着时本工具收不到任何状态帧，自动切换会失效。
> 两者只能留一个：关掉驱动，本工具独立工作（驱动默认不随系统自启）。

## 快速上手

### 安装

**第 1 步：解压到固定位置**

下载 Release 里的 zip，解压到一个之后不会动的目录，例如 `C:\Tools\HECATE-DockAudioSwitch`。
不要放在下载文件夹或桌面 —— 计划任务按绝对路径启动，目录挪了就得重装。

**第 2 步：跑一次安装脚本**

右键 `install.ps1` → **以管理员身份运行**，UAC 弹窗允许即可。

或者在解压目录里打开 PowerShell：

```powershell
Start-Process powershell -Verb RunAs -ArgumentList '-ExecutionPolicy','Bypass','-File','install.ps1'
```

> 注：需要管理员只是为了注册一个「登录时自启」的计划任务；工具平时以普通权限运行，不需要提权。

**第 3 步：验证**

把耳机拿起，看音频播放设备是否会自动切到耳机。再放回底座各一次，看音频播放设备是否从耳机退出。看同目录下的 `g5-switch.log` 会有如下记录：

```
[00:29:14.919] frame: cmd=0x0A [...] -> inuse
[00:29:15.258] audio: HEADSET (Show hr=0)
```

### 卸载

右键 `uninstall.ps1` → 以管理员身份运行，然后删掉整个目录。

会删掉计划任务、结束进程，并把耳机音频端点恢复成可见状态 —— **设备回到安装前的样子，不需要重启**。

## 进阶

### 问题分析

**症状**：耳机底座 USB 插上电脑后，音频出现 "HECATE XXX" 设备。如果将该设备设为默认音频。那么将耳机放回底座后，音频不会自动切出，仍保持耳机播放，最终导致系统静音。如果不将该设备设为默认音频，那么无论提起还是放下耳机，音频都不会有任何变化。

**根因**：

1. 底座同时是 2.4G 接收器和充电座，通过一根 USB 线接电脑，向系统枚举了一个 USB 音频设备（`MI_00`）
2. 耳机开关机只影响 2.4G 那一侧的射频链路，**不影响 USB 侧的枚举** —— 底座并不知道（也不告诉系统）耳机已经关机
3. Windows 只在端点"出现/消失"时才自动切换播放设备。这里两个事件都没有发生，所以它永远不切

因此任何"等设备断开再切换"的思路都不成立，必须**主动让端点消失**。

**为什么不用其他做法**：

| 做法 | 问题 |
|---|---|
| 用 `pnputil` 停用音频接口 | 需要管理员；反复 disable/enable 会把设备推进"等待系统重启"；拆掉 USB 音频接口还会让底座自身状态变化，导致误判和自激 |
| 只切换默认播放设备 | 端点还在，个别程序仍会往"已经没人接收"的设备送音频 |
| 等 Windows 自己切 | 端点从不消失，永远等不到事件 |
| 直接禁用耳机音频设备 | 需要管理员，且禁用后想用耳机还得再启用 |

**本方案不适用的情形**：

- 耳机放回底座后**仍然保持开机在线**（不播报"关机"）→ 底座状态不变，无法判断
- 底座只负责充电、音频走**独立的 2.4G 接收器** → 直接把接收器插到带开关的 USB 口上更简单
- 有线版本（`Pid_A229`）理论相通但未验证

### 方案原理

一句话：**监听底座主动推送的状态帧，据此隐藏/显示耳机音频端点。**

#### 1. 数据来源：底座的主动推送

底座在 HID 控制通道 `MI_04 & Col03` 上会**主动推送** 64 字节状态帧，不需要主机查询：

```
D0 35 BB <cmd> <sub> <payload...> ... 04
│  └──┴── VID = 0x35BB（小端）
└─ 固定帧头                                末字节恒为 0x04
```

判据只看 `0x0A` 帧的第 5~10 字节：

| 状态 | `0x0A` 帧载荷（第 5~10 字节） | `0x03` 帧第 5 字节 | 含义 |
|---|---|---|---|
| **使用中** | `01 64 00 01 01 09` | `EF` | 耳机开机，有完整遥测（`0x64` = 100 电量）|
| **在底座** | `00 00 00 00 00 00` | `01` | 耳机已关机，读不到任何遥测 |
| 忽略 | `00 64 01 00 00 00` | — | **不是推送值**，见下方第 1 坑 |

完整帧示例：

```
使用中   D0 35 BB 0A 00 01 64 00 01 01 09 01 01 03 ... 04
在底座   D0 35 BB 0A 00 00 00 00 00 00 00 01 01 03 ... 04
```

#### 2. 四个关键的坑

1. **不要主动查询。** 自己写 `0x0A` 查询，底座会回一条**与耳机状态无关的过期记录**（恒为 `00 64 01 00 00 00`），
   早期版本就是因为主动轮询而长期判断错误。
2. **全零 = 在底座**，不是"数据异常"。它表示耳机已关机、没有遥测。
3. **`01 64 00 ...` = 使用中**，不是"在充电"。曾把第 5 字节当充电标志，结果电池充满后标志消失，
   被误判成"已经离开底座"，于是音频被切到已经关机的耳机上。
4. **推送是事件驱动的**，没有周期性心跳。所以启动时先用 `last-state.txt` 里的上次状态恢复一次。

#### 3. 切换动作

用 `IPolicyConfig::SetEndpointVisibility`（即「声音设置」里"禁用设备"背后的接口）隐藏/显示端点，
再用 `SetDefaultEndpoint` 指定默认设备。**不碰 PnP 设备状态，不需要管理员，不影响充电。**

```
拿起耳机 → 推送 inuse  → 显示耳机端点 + 设为默认播放设备
放回底座 → 推送 docked → 隐藏耳机端点 + 默认设备回到原设备
```

#### 4. 兜底机制

- **每秒校正一次**：按当前已知状态幂等地把端点可见性和默认设备拉回目标值，
  防止 Windows 在耳机开关机时把默认设备挪走
- **记住原设备**：切到耳机前把当时的默认设备存进 `last-default.txt`，切回时精确恢复
- **手动优先**：执行 `G5DockSwitch.exe headset|external` 会写 `override.txt`，
  守护进程保持你的选择，直到下次耳机状态变化

### 编译与改进

不需要 .NET SDK 或 Visual Studio，Windows 自带的 C# 编译器就够：

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
# 产物: dist\G5DockSwitch.exe（约 18 KB）
```

源码只有一个文件：[src/G5DockSwitch.cs](src/G5DockSwitch.cs)，约 640 行，无第三方依赖。

**换型号适配**：把 `config.ini.example` 复制成 `config.ini`（与 exe 同目录）后修改：

```ini
vid=35BB
pid=A228
desc=HECATE
iface=MI_04&Col03
```

`desc` 是音频设备描述的**前缀**，`iface` 是承载状态帧的 HID 集合。

**诊断工具**：

```powershell
G5DockSwitch.exe --probe          # 打印自动识别到的设备路径/端点/当前状态，并监听 3 秒
G5DockSwitch.exe --capture 60     # 录 60 秒原始帧到 capture.log
```

完整的协议逆向记录（帧格式、字段推测、踩坑过程）见 [docs/protocol.md](docs/protocol.md)。

## 常见问题QA

**Q1：装好了，但拿起 / 放下没反应？**

A：按顺序排查：

1. 放回底座时耳机**有没有播报"关机"**？没有的话说明耳机仍保持开机，底座状态不会变，本方案不适用 ——
   建议改用 [SoundSwitch](https://github.com/Belphemir/SoundSwitch) 之类设一个切换热键
2. 运行 `G5DockSwitch.exe --probe`，看 `hid path` 和 `endpoint id` 是否都是实际路径。
   显示 `(not found)` 说明型号不在自动识别范围，需要改 `config.ini`
3. 运行 `G5DockSwitch.exe --capture 60`，期间反复"拿起 → 放回"两三次，
   把 `capture.log` 和 `probe.txt` 贴到 issue 里

**Q2：判断反了（拿起切扬声器、放下切耳机）？**

A：不同批次的固件可能用了相反的编码。用 `--capture` 录一段，把两种状态下的原始帧贴出来即可适配。

**Q3：会不会改我的驱动或固件？**

A：不会。它只用 Windows 自带的音频接口做两件事：把耳机音频设备"隐藏/显示"、切换默认播放设备，
等同于你在「声音设置」里手动点禁用/启用。卸载即恢复。

**Q4：会影响充电和保修吗？**

A：不会。充电是硬件行为，工具碰不到；也没有修改任何设备状态或驱动。

**Q5：需要一直开着漫步者驱动吗？**

A：不需要。实测把 HECATE 驱动完全关闭，工具照常工作。

**Q6：重启之后还有效吗？**

A：有效，登录时自动启动。

**Q7：为什么不能放在下载文件夹或桌面？**

A：计划任务按绝对路径启动，目录挪走或改名后任务就找不到程序了。要移动的话，移动后重新运行一次 `install.ps1`。

**Q8：Windows 大版本更新 / 耳机固件升级后会失效吗？**

A：系统更新一般不影响。固件升级后报文格式有可能变，届时用 `--capture` 录一段反馈即可适配。

**Q9：别的型号能用吗？**

A：目前只在 HECATE G5 MAX 底座版上验证过。同厂其他底座型号很可能协议相通，`--probe` 试一下就知道；
不行就用 `capture.log` 反馈。

**Q10：安全吗？**

A：开源、单文件、无第三方依赖，可用 `build.ps1` 自行编译，不联网、不收集任何数据。

**Q12：开着漫步者驱动时自动切换不工作？**

A：这是预期行为。驱动（HECATE.exe）和本工具会**争抢底座同一份 HID 数据流**，谁先读走就归谁。
驱动开着时，状态帧全被它读走，本工具收不到任何数据。解决办法只有一个：**关掉驱动**。

驱动默认不随系统自启，所以正常情况下重启后它不会自己出现；如果你手动打开了它，就会盖掉自动切换。
工具的日志里会有明确提示：

```
warn: Edifier driver (HECATE.exe) is running - it consumes the dock HID reports, auto-switch is inactive until it is closed
```

**Q13：重启后自动切换失效？**

A：v0.1.1 之前的版本存在这个缺陷：开机时如果句柄在底座完成枚举之前就被打开，它会一直是"哑"的。
v0.1.1 起加了两项保护：启动后延迟 5 秒再打开设备；以及**连续 120 秒收不到任何帧就自动重开句柄**。
日志里对应这两行：

```
hid: listening ...
hid: no frames for 120s, reopening handle
```
**Q11：想手动强制切一下？**

A：在解压目录执行：

```powershell
G5DockSwitch.exe headset     # 切到耳机
G5DockSwitch.exe external    # 切到扬声器
```

手动切换会保持住，直到你下次拿起或放下耳机。
